The `POST /api/llm_call` endpoint provides a lightweight, stateless interface to the underlying language model. It accepts a freeform text prompt, forwards it directly to Gemini 2.5 Flash through LiteLLM, and returns the complete response in a single JSON object. There is no RAG retrieval, no conversation history, and no token usage tracking — the call is fire-and-forget at the inference layer.

This endpoint is useful for testing model behaviour, running one-off transformations, or building internal tooling that does not require the full chat pipeline. For production conversational AI, use [`POST /api/chatConversation`](/api/chat/conversation) instead.

## Endpoint

```
POST /api/llm_call
```

**Authentication:** Not required — authentication is currently disabled on this endpoint.

<Warning>
  The authentication guard for this endpoint is commented out in the source code. Do not expose this endpoint on a publicly reachable server without adding your own access controls, as it allows unauthenticated prompt execution against your LLM quota.
</Warning>

---

## Request Body

```json
{
  "data": {
    "prompt": "Your prompt here"
  }
}
```

<ParamField body="data.prompt" type="string" required>
  The full prompt text to send to the model. The prompt is passed directly to the LLM with no system context, RAG documents, or conversation history prepended.
</ParamField>

---

## Response

```json
{
  "statuscode": 200,
  "data": "<LLM response text>"
}
```

<ResponseField name="statuscode" type="integer">
  `200` on success. This field is always present in the response body (in addition to the HTTP status code).
</ResponseField>

<ResponseField name="data" type="string">
  The complete text response generated by the model. Returned as a plain string, not streamed.
</ResponseField>

---

## Model

Requests are routed to **Gemini 2.5 Flash** via [LiteLLM](https://docs.litellm.ai/) using the identifier `gemini/gemini-2.5-flash`. LiteLLM handles credential resolution and provider-level retry logic.

<Tip>
  Gemini 2.5 Flash is optimised for low-latency, high-throughput inference. For complex multi-step reasoning tasks you may want to explore using the full `chatConversation` pipeline, which provides conversation history and grounded RAG context.
</Tip>

## Comparison: llm_call vs chatConversation

| Feature | `/api/llm_call` | `/api/chatConversation` |
|---------|----------------|------------------------|
| Authentication | ❌ Not required | ✅ Bearer token required |
| RAG retrieval | ❌ No | ✅ Yes |
| Session persistence | ❌ No | ✅ Yes |
| Token usage tracking | ❌ No | ✅ Yes |
| File attachments | ❌ No | ✅ Yes |
| Streaming response | ❌ No (full response) | ✅ SSE stream |
| Follow-up resolution | ❌ No | ✅ Yes |

## Examples

### curl

```bash
curl -X POST http://localhost:8081/api/llm_call \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "prompt": "Explain the difference between supervised and unsupervised learning in two sentences."
    }
  }'
```

**Example response:**

```json
{
  "statuscode": 200,
  "data": "Supervised learning trains a model on labelled data where the desired output is known, guiding it to learn the mapping from inputs to outputs. Unsupervised learning finds hidden structure in unlabelled data without any predefined correct answers."
}
```

### Python (requests)

```python
import requests

url = "http://localhost:8081/api/llm_call"

payload = {
    "data": {
        "prompt": "Explain the difference between supervised and unsupervised learning in two sentences."
    }
}

response = requests.post(url, json=payload)
response.raise_for_status()

result = response.json()
print(result["data"])
```

## Error Responses

| Status | Detail |
|--------|--------|
| `500` | `An unexpected error occurred: <error>` — the LLM call failed. This may indicate an invalid API key, a network error reaching the LiteLLM proxy, or an upstream provider outage. The raw exception message is included in the detail string. |
