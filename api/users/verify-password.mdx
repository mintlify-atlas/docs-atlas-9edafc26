title: "POST /api/verifyPassword — authenticate and get JWT"
sidebarTitle: "Verify Password"

The `verifyPassword` endpoint is the primary login mechanism for Voice Agent. Submit a registered email address and its matching password, and the server will validate the credentials and return a short-lived JWT. Every protected endpoint in this API requires that token in the `Authorization` header. If the credentials are invalid, the response returns `returnCode: 7` (`INVALID_PASSWORD`) — no token is issued.

```http
POST /api/verifyPassword
```

## Authentication

<Note>
  This is a **public endpoint** — no `Authorization` header is required to call it. Successful calls to this endpoint are how you _obtain_ the bearer token needed for all other authenticated routes.
</Note>

## Request Body

All request bodies in this API are wrapped in a `DataRequest` envelope:

```json
{
  "data": { ...payload... }
}
```

<ParamField body="data" type="object" required>
  The `DataRequest` wrapper object.

  <Expandable title="data fields">
    <ParamField body="emailId" type="string" required>
      The registered email address of the user. Must be a valid email format (e.g. `user@example.com`).
    </ParamField>

    <ParamField body="password" type="string" required>
      The user's plaintext password.
    </ParamField>
  </Expandable>
</ParamField>

## Response

All responses follow the `APIResponse` envelope:

```json
{
  "dataResponse": {
    "returnCode": 0,
    "responseDateTime": "2024-01-15T10:30:00",
    "description": "Password verified successfully"
  },
  "data": {
    "authToken": "<jwt>",
    "tokenType": "bearer"
  }
}
```

<ResponseField name="dataResponse" type="object">
  Top-level metadata about the result.

  <Expandable title="dataResponse fields">
    <ResponseField name="returnCode" type="integer">
      Machine-readable result code. `0` indicates success. See [Error Codes](#error-codes) below for failure values.
    </ResponseField>

    <ResponseField name="responseDateTime" type="string (ISO 8601)">
      Server timestamp of when the response was generated.
    </ResponseField>

    <ResponseField name="description" type="string">
      Human-readable summary of the outcome, e.g. `"Password verified successfully"`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="data" type="object">
  Present only on success (`returnCode: 0`). Contains the authentication token.

  <Expandable title="data fields">
    <ResponseField name="authToken" type="string">
      A signed JWT. Include this value in the `Authorization` header of subsequent requests as `Bearer <authToken>`. The token encodes the user's `id`, `fullName`, `emailId`, `mobileNumber`, `role`, and expiry claim.
    </ResponseField>

    <ResponseField name="tokenType" type="string">
      Always `"bearer"`. Indicates the token scheme expected by the `Authorization` header.
    </ResponseField>
  </Expandable>
</ResponseField>

## Example

```bash
curl -X POST https://your-api-host/api/verifyPassword \
  -H "Content-Type: application/json" \
  -d '{
    "data": {
      "emailId": "alice@example.com",
      "password": "s3cr3tP@ss"
    }
  }'
```

**Successful response:**

```json
{
  "dataResponse": {
    "returnCode": 0,
    "responseDateTime": "2024-01-15T10:30:00.123456",
    "description": "Password verified successfully"
  },
  "data": {
    "authToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "tokenType": "bearer"
  }
}
```

**Failed response (wrong password):**

```json
{
  "dataResponse": {
    "returnCode": 7,
    "responseDateTime": "2024-01-15T10:30:00.123456",
    "description": "Invalid password"
  },
  "data": null
}
```

## Using the Token

Attach the returned `authToken` to every subsequent authenticated request:

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

The token expires after the duration configured in the `authToken_EXPIRE_MINUTES` environment variable. Once expired, re-authenticate via this endpoint to obtain a fresh token.

## Error Codes

| `returnCode` | Name               | Description                                                      |
|--------------|--------------------|------------------------------------------------------------------|
| `0`          | `SUCCESS`          | Credentials valid; `authToken` included in `data`.               |
| `7`          | `INVALID_PASSWORD` | The email/password combination did not match any active account. |
